# CUDA 性能复测

## 条件与方法

- 显卡：NVIDIA GeForce RTX 3060 Ti，Windows WDDM，CUDA Toolkit 12.4。
- 旧版来源：提交 `8f36e6c` 对应的 EXE 与 PTX；新版替换 CUDA 内核，并调整默认线程数。
- 配置：`continuous=10`、`dreamAddressSubstr=[]`、`steps=8`。
- 用户已停止原有地址搜索进程；各项测速串行执行。
- 每项测量 3 次，每次 `-benchmark -duration 5s`，第二轮逆序，减少测试先后和显卡升温造成的偏差。
- 测速模式不保存私钥，计时不包含驱动加载、自检与随机私钥初始化。下表是程序最终输出的每秒地址数，平均值为三次结果的算术平均。

## 结果

| 内核与线程数 | 第一次 | 第二次 | 第三次 | 平均地址/秒 |
| --- | ---: | ---: | ---: | ---: |
| 旧内核，4096 线程 | 4,018,532 | 4,155,749 | 4,148,897 | 4,107,726 |
| 新内核，4096 线程 | 7,186,360 | 7,018,617 | 7,322,641 | 7,175,873 |
| 新内核，65536 线程 | 20,262,076 | 19,964,897 | 20,404,581 | 20,210,518 |

相同线程数下约提升 74.7%；新版默认吞吐量约为旧版默认的 4.92 倍。后一个比较同时包含算法优化与线程数调整，不能全部归因于算法改进。

参数摸底还测试了 16384、32768 线程和每批 16、32 次迭代。在本机，65536 线程、每批 8 次的结果较好，因此仅提高默认线程数，保留每批 8 次迭代。其他显卡和桌面负载应重新测量，不能直接套用本机吞吐量。

## 实现变化

1. 模逆仍计算 `a^(p-2)`，使用固定加法链，以 255 次平方和 15 次额外乘法完成。各中间指数为 `2^k-1`，最终指数为 `2^256-2^32-979`，与 secp256k1 的 `p-2` 相同。
2. 地址匹配先用忽略大小写的字符进行预筛选。无匹配可能时跳过 EIP-55 哈希；纯数字条件直接判断；存在字母命中可能时继续原有的完整大小写校验。
3. 默认搜索线程从 4096 提高到 65536，提高 GPU 并行度。默认显存缓冲区约为 18 MiB；初始化 65536 个独立随机种子会增加启动时间。

私钥仍由 CPU 使用安全随机源生成，GPU 仍只接收公钥。所有最终命中仍须由 Go 重算地址和匹配规则，复核通过后才能写入文件。

## 正确性验证

- 1024 组素域加、减、乘、逆与 Go 大整数逐项比较，包含零、单位元、接近素数上界的边界值与随机值；零的测试约定返回零，不作为有效模逆使用。
- 两批随机私钥地址与 CPU 比较，覆盖点加倍和跨批次状态延续。
- 无穷远点仍会触发停止。
- 1024 个随机或构造地址、10 组匹配规则逐项与 CPU 比较，覆盖连续数字、连续字母、混合大小写子串、完整地址与多条件组合。

```powershell
$env:CGO_ENABLED = '0'
$env:CUDA_TEST = '1'
go test -count=1 -v ./...
go vet ./...

# 使用当前配置进行测速；不会保存钱包
./go-vanity-eth.exe -backend cuda -benchmark -duration 10s

# 对比相同内核的线程数影响
./go-vanity-eth.exe -backend cuda -lanes 4096 -steps 8 -benchmark -duration 10s
./go-vanity-eth.exe -backend cuda -lanes 65536 -steps 8 -benchmark -duration 10s
```

显卡承担桌面显示或其他计算时，可降低 `-lanes` 或 `-steps`。短时间测试及命中频繁的配置还会受到 CPU 复核、输出与文件同步开销影响。
